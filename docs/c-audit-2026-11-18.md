# Focused Windows C audit, 2026-11-18

## Native execution follow-up

After explicit owner authorization for Shure playback/capture, the native matrix
exposed one additional medium production finding, W9: `wa_capture` advertised
engine-rate capture positions as application frames during Windows resampling.
At 16 kHz, packet positions advanced by 480 while packet data normally contained
160 frames, causing false unknown gaps/epoch changes. The capture worker now
records its actual mix rate at client construction; converted capture omits raw
position validity and reports the host correlation as estimated. SDK metadata
is validated and freed on the same COM owner; there is no core resampling or ABI
change. `wasapi_buffers` checks converted/equal-rate timestamp flags independently.

The retained first matrix had 24 failed lower-rate and eight successful 48 kHz
cases. After this fix, all 32 strict format/startup cases passed with meaningful
input. Simplex capture revealed a separate harness bug (nonzero queue slots on
the disabled playback leg); the correct core rejection and successful correction
are retained. Thirty actual lifecycle cycles and all four linkage/configuration
samples passed. Matching LLVM 23 ASan passed 9/9 device-free tests plus native
F32/S16 duplex; an independent negative heap probe proves runtime interception.
The original LLVM 19 startup failure remains historical evidence, not suppressed.

The final strict 600.009 s phase has zero sustained capture/render/reference loss
and no capture logical/epoch changes, with balanced two-allocation teardown.
Separate timing telemetry retains 178 future SDK correlations among 1,004 valid
48 kHz observations, alongside explicitly conditional nonnegative quantiles.
Unknown uncertainty prevents a calibrated latency interpretation. This is a
timestamp-quality observation requiring independent fixture work, not an
established Hail memory/transport defect or permission to clip timestamps.

The level helper is qualification-only, validates capture direction/arguments,
uses COM on its owner, and never handles PCM. Input changes require an explicit
test flag and are restored from saved readbacks in parent `finally` paths. No
default/privacy/security controls change. See [physical results](native-windows-physical-results.md)
for exact source/configuration and execution limits. The owner-coordinated USB
loss/reopen trial now passes: terminal DEVICE_LOST, application/native retirement,
fresh endpoint incarnations/clock domains and three balanced allocations/frees.
The first no-removal timeout is retained, not counted as a passing loss test.
The controlled paired fixture remains pending. The original pass below is preserved.

## Initial implementation-only pass

device-free SDK-seam defect or a source-confirmed defensive/error-path defect;

Microsoft's [capture buffer contract](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudiocaptureclient-getbuffer)
defines empty-success and timestamp/silence handling. Buffer leases remain on
their COM worker; no production SDK interface is accessed by test control threads.
The capture release fix was found by a failing seam test, not inferred solely
from a text search.

Memory/geometry review: capture and render chunks are bounded by native capacity
and application quantum; frame-to-byte copies use validated mono/stereo widths.
The native test uses fixed PCM buffers, bounded histograms and a sized/aligned
allocation ledger. The public role contract is preserved by joining the I/O
thread before control performs its explicit stale write or final close.
Deadlines call process termination without manually freeing native-reachable
storage. Worker exit/notification retirement remains necessary for reclamation.
No public record/signature or mandatory dependency changed.

The native PCM oracle has independent hand-authored negative cases for channel
corruption, sample skips, old-after-new generations and nonrepresentable values.

minimum nonzero requirement. The signed-fixture placeholder is rejected before
device access; its positive validation still requires a real approved manifest.
