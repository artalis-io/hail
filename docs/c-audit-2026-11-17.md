Audit only; no production changes applied.

not apply to this PCM library. Reviewed all 14 files in `src/` and `include/`,

### M1: teardown must establish physical retirement

ALSA sets `exit`, ignores `pthread_join` failure, closes PCM handles, and returns
to `ha_stream_close_finish`, which frees the allocation. The worker accesses
both stream and backend storage outside its per-leg admission gates. Therefore
closed audio gates alone cannot replace joining that worker.

WASAPI similarly ignores the final thread wait result in both context and stream
cleanup, closes handles and clears backend state. A failed wait is not evidence
that the worker has exited. The context cleanup interface can return a failure;
the stream cleanup interface is currently `void`, so its fallible retirement
work must happen earlier. Apply the same rule to unpublished failed-open state.

This finding concerns exceptional native synchronization failures. No ordinary
successful teardown race or actual use-after-free was observed. Test with an
injected failed barrier: storage and native resources must remain owned until
a later successful retirement, with no second worker or double cleanup.

### M2: failed native abort is observable, not successful stop

After `alsa_stop` returns `HA_OK`, core stop progression resets queues,
increments playback generation and reports `HA_STOPPED`. A failed
`snd_pcm_drop` currently cannot prevent that acknowledgement. Depending on the
native failure, queued playback may not have been aborted; device loss also
loses its native failure result. This conflicts with the
[backend lifecycle contract](backend-authoring.md).

Inject a drop failure on each leg separately and together. Verify both legs are
attempted, no successful stop event is emitted, failure reaches stream status,
and explicit close still retires and joins the worker safely.

### M3: reject unsupported packing before interpreting PCM

The buffer offset, size, divisibility and maximum frame checks bound the memory
span, but do not make a negative stride equivalent to packed forward PCM.
The current predicate admits every negative value. This is a validation and
audio-integrity defect; the reviewed checks do not demonstrate an out-of-bounds
read. Test negative, zero, exact positive and mismatched positive strides,
including empty buffers, without requiring real audio hardware.

## Resolution pass: 2026-11-17

The initial audit above describes the base revision. The subsequent working-tree
fixes resolve all four findings; they do not retroactively change that evidence.

| Finding | Resolution | Regression evidence |
|---|---|---|
| M1 | ALSA joins in fallible retire and retains resources on failure. WASAPI retire checks thread termination before closing its handle; context teardown checks both EXIT acknowledgement and the final wait. Open failure cleanup is owned by core, retaining unretired streams against existing stream/memory limits for poll/destroy retry. CoreAudio/PipeWire partial opens now leave cleanup to that same owner. | `retirement` tests public-handle failure, retained allocation/quota, poll/destroy retry, successful final cleanup and published close failure. `alsa_faults` tests failed join/retry without closing PCM early. `wasapi_retirement` injects failed wait/signal and distinguishes EXIT acknowledgement from final thread termination; compiled, not executed here. |
| M2 | ALSA stop attempts both legs, returns the first mapped drop failure, and cannot publish successful STOPPED on that failure. Close retirement joins and closes native resources independently. | `alsa_faults` checks each leg failing, both failing, both attempted, terminal failure state/event and successful stop; debug and ASan/UBSan runs passed. |
| M3 | Negative capture stride is rejected before PCM interpretation. Zero (unspecified packed stride) and exact positive bytes/frame remain accepted. | `pipewire_buffers` drives the real process callback with negative, extreme negative, mismatched positive, zero and exact strides, with empty/nonempty buffers; verifies PCM and buffer-lease return. Debug and ASan/UBSan runs passed. |
| L1 | GCC/Clang library builds enable `-Wformat=2`; supported hosted compilers enable `-fstack-protector-strong` after a compiler check. Freestanding builds omit the stack-protector requirement. | Strict macOS/Linux/Windows cross-builds passed; hosted flags are present, and freestanding plus backend-free builds passed. |
