## Safety review

| Area | Source anchors and judgment |
| --- | --- |
| Allocation and bounds | `queue.c:hail_add/hail_mul/hail_format`, `core.c` planning/open/close and `hail_internal.h` storage layout use checked sizing and exact allocator records. Failed opens keep unpublished storage charged until retirement. `hosted.c` isolates hosted allocation; SDK allocations retain SDK release rules. |
| PCM leases | `native.c:hail_native_capture/hail_native_render`, `backend_wasapi.c`, `backend_coreaudio.c:ca_audio`, `backend_pipewire.c:stream_process`, and ALSA worker validate bounded native geometry before transfer. Source review followed release paths and packet/stride/frame conversions. The standalone probe checks native capacity, packet maxima, format and marker minima. |
| SPSC and ownership | `queue.c` ring publication uses release/acquire, consumer-owned partial offsets and bounded copies. Core application gates and per-leg native gates are distinct. Capture drops newest when full; render substitutes silence without waiting for application PCM. Concurrent instruction-level behavior is not proved by sequential fuzz models. |
| State/error publication | `core.c` serialized lifecycle and `native.c` snapshots/error publication retain the first terminal payload. Flush revokes render writes, snapshots the consumer cutoff and advances content generation; capture state remains independent. |
| Retirement | Core reclamation requires native retirement and application quiescence. WASAPI waits for worker termination, ALSA checks join, CoreAudio separates stop/uninitialize/callback barriers, and PipeWire removes its RT hook through the data loop. Gates alone do not establish SDK retirement. Failed initialization/retirement remains retained and retryable. |
| Timing | Checked interpolation/overflow and validity bits remain separate from playback generations. WASAPI converted capture invalidates engine positions in application frame units. Probe tick-to-ns conversion uses quotient/remainder; run durations and packet positions are bounded. |
| Diagnostic lifetime | Default-off SDK records live in the worker-owned backend prefix. Test reads require retirement before backend storage is freed. Independent clients own separate static rings; bounded synthetic examples add no public API or application callback. |
| Build and dependencies | Strict warnings, symbol checks, installed C/C++ consumers and portable dependency scans passed. The only platform conditional in the reviewed portable/public boundary scan is the public Windows ABI decoration. Native SDK implementation stays in adapters and test tools. |

Unsafe-copy/allocation/retirement searches were followed through concrete control
flow; bounded copies and SDK frees are not findings by themselves. No additional
source-confirmed failure path was established from hypothetical malformed SDK
properties or unsupported native-handle failures. Such cases remain a review
limit rather than asserted defects.
